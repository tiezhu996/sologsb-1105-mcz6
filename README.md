# 老地图图幅编目与地名对照台

面向古地图整理者和地方志研究者，将老地图按图幅编目，登记年代、比例尺、投影和扫描件，并建立古今地名对照及沿革线索。应用为纯前端单页程序，所有资料保存在浏览器本地。

## Docker 一键启动

```bash
cp .env.example .env && docker compose up -d --build
```

服务默认映射到宿主端口 `21805`。停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

应用使用 IndexedDB 持久化数据，Dexie 数据库名为 `gboldmap-db`。数据库包含 `sheets`、`scans`、`placePairs`、`histories`、`retirements` 五个对象仓库：

- `version(1)` 建立首版索引结构，并在首次创建数据库时写入图幅、扫描件、地名对照和沿革种子数据。
- `version(2)` 保持现有索引并对已有图幅执行 `schemaRev = 2` 的回填迁移，用于演示后续结构升级路径。
- `version(3)` 新增 `retirements` 撤编登记表，保存撤编时固定的资料快照（扫描件、地名对照、沿革清单）、受影响邻接图旧值与检查点状态。

刷新或关闭页面不会丢失新增记录；浏览器站点数据被清除时会重新触发首次种子数据写入。

## 撤编流程（图幅详情页办理）

馆员常在两个页签同时整理同一图幅，撤编因此只允许在详情页进入专门的确认页 `/sheets/:id/retire` 办理：

1. **打开确认页即固定资料**：现场从数据库读取并固定该图幅当前的扫描件、地名对照和沿革清单，生成快照指纹。
2. **跨页签重新核对**：其他页签对扫描件、地名、沿革或邻接关系的修改会通过 `BroadcastChannel` 即时提示“快照已过期”；确认提交时还会在同一事务内重读数据并比对指纹做最终兜底，必须重新核对并固定后才能确认。
3. **一次写入**：先持久化检查点（含完整快照），随后在单个 IndexedDB 事务内一次写入撤编状态、资料快照登记和受影响邻接图（从邻接图的邻接图号中摘除本图）。事务要么全部生效要么整体回滚；若写入中断，检查点仍在，可一键从检查点恢复，应用下次启动也会自动回收遗留检查点，不会留下半套撤编结果。
4. **撤编后**：编目台和导出清单默认不显示已撤编图幅（编目台可勾选“显示已撤编图幅”）；详情页仍可查看原资料，并可从快照一键撤销撤编，恢复图幅原状态与邻接关系。

## 核心功能与路由表

| 路由 | 核心功能 |
| --- | --- |
| `/sheets` | 按年代、比例尺和状态筛选图幅（默认隐藏已撤编），内联新建图幅，查看扫描件数、地名数与邻接缺编提示 |
| `/sheets/:id` | 查看编制摘要、扫描件条目、主用件切换、图内地名检索及 JSON 导出；已撤编图幅只读并可从快照撤销 |
| `/sheets/:id/retire` | 撤编确认页：固定扫描件/地名/沿革快照、跨页签变更核对、检查点与原子提交 |
| `/places` | 古今地名双栏对照，按类型和确定度筛选，对古名、今名、异写及图上方位反向查询并高亮 |
| `/places/:id/history` | 按年代排列沿革时间线，新增初置、改名、迁治或废置记录 |
| `/sheets/:id/neighbors` | 按四至排列邻接图幅，显示主用扫描件、缺编提示与拼合预览 |
| `/`、未匹配路径 | 自动跳转到 `/sheets` |
